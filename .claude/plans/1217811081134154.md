# PART 1 — In simple words

## What the system does today
When staff upload a refund or settlement spreadsheet from CCAvenue or BillDesk, the system saves the upload, and also builds a new spreadsheet of refunds to send back. All of these files are stored in the `assets` folder. That folder is the "shop window" of the website: any file in it can be opened by anyone who knows its web address, with no login.

## What is wrong with it
The files hold customer refund details (reference numbers, order numbers, amounts). The names are easy to guess (for example `20261014031500_BulkUpdateRefund.xls` is just the date and time, and uploads are `<timestamp>-<original name>`). So a stranger could try addresses until one opens, and read another customer's refund data. The settlement list screen also links straight to the file address, so the address is shown to staff and can leak. The Kotak settlement files had exactly this problem and were already fixed.

## What we are going to change
Move the files into the private `internal-excel-files` folder, which the web server refuses to serve directly. Staff download them through a new page that first checks they are logged in and allowed to see the payment-gateway section, then hands over the file. This is the same method used for the Kotak files.

## What could go wrong
- Files already sitting in the old `assets/...` folders on the servers stay publicly readable until they are moved or deleted by hand. Code alone cannot fix that.
- Old download links bookmarked by staff stop working (they point at the old folder).
- If the new private folders do not exist on a server, saving fails. The code creates them when missing, as the Kotak fix does.

# PART 3 — The technical version

## Root cause
CCAvenue and BillDesk settlement/refund files are written to, and linked from, web-served `assets/` paths with guessable names. Verified by reading the code on `onestackcbs` (line numbers still match the task):

`service/CcavenueSettlement.php` (all paths under `application/modules/mobile_app/controllers/`):
- `:52`, `:159` — upload dir `assets/mobile_app/ccavenue-settlement-file/` (customer settlement uploads; `:55`, `:162` mkdir it).
- `:305` — `$savedFilepath = FCPATH.'assets/mobile_app/ccavenue-settlement-file/settlement/'.$fileName;` generated refund workbook, `$fileName = date('Ymdhis')."_BulkUpdateRefund.xls(x)"` (`:290-ish`).
- `:314` — `return base_url()."assets/mobile_app/ccavenue-settlement-file/settlement/".$fileName;` public URL returned (the `downloadFile` key of the JSON at `:239-243`).
- `:354` — upload dir `assets/mobile_app/ccavenue-settlement-file/refund/`.
- `:511` — list screen link: `'href' => base_url('assets/mobile_app/ccavenue-settlement-file/settlement/'.$value['file_name'])`.

`products/BillDeskMaster.php`:
- `:138` — upload dir `assets/billdesk-settlement-files/` (no mkdir; `$path` reused at `:164` to open the upload).
- `:254` — `$savedFilepath = FCPATH . 'assets/ccavenue-settlement-file/settlement/' . $fileName;` (a CCAvenue path copy-pasted into the BillDesk controller).
- `:261` — `return base_url() . "assets/ccavenue-settlement-file/settlement/" . $fileName;`.

Reference fix, `a5e9e2433b` on `onestackcbs`: moved Kotak files to `internal-excel-files/settlement-file/`, added `mkdir` guards, added `downloadSettlementFile()` / `downloadUtrSettlementFile()` (`checkSubChildControllerAccess('service','onestack_services','payment_gateway','display_action')` + `logged_in()` + `basename()` + `force_download`), two routes in `routes.php`, `.gitignore` entries, and added `txt` to `internal-excel-files/.htaccess`.

`internal-excel-files/.htaccess` already denies every non-127.0.0.1 request to the folder (RewriteRule block, any extension), so `.xls` is blocked even though the `<If>` regex lists only `xlsx|csv|pdf|jpg|png|docx|txt`.

## How it will be fixed
Mirror `a5e9e2433b` for the two controllers:
1. New private dirs: `internal-excel-files/ccavenue-settlement-file/` (+ `settlement/`, `refund/`) and `internal-excel-files/billdesk-settlement-files/`.
2. Point every path above at them, with `if (!file_exists($dir)) mkdir($dir, 0775, true);` (0775, matching the mkdir hardening already on production, e.g. `CcavenueSettlement.php:55`).
3. Add `downloadSettlementFile($filename)` to `CcavenueSettlement` (same guards as the Kotak method; `basename()`; look in `settlement/` only), a route for it, and make `:314` and `:511` use that route.
4. `BillDeskMaster::download_refund()` result is not shown to anyone (`:208` assigns it, then `exit`), so BillDesk gets the path change only, no download route. Its return URL at `:261` is changed to the CCAvenue download route only if still returned; otherwise left as the same new route (see step 6).
5. `.gitignore`: ignore the new dirs' contents, keep `.gitkeep` files (as the Kotak commit did).
