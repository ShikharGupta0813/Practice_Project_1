# PART 1 — In simple words

## What the system does today
Before our software can talk to Kotak Bank's payment system, it has to prove
who it is, like showing an ID card and a password at a bank counter. Kotak
then gives back a temporary pass (valid for a short time) that lets us make
requests.

One piece of our code does exactly this. Today it:

1. Has the ID and the password typed directly into the code, so anyone who can
   see our code can see the password.
2. After talking to Kotak, writes a note into a diary file on the server. The
   note contains the ID, the password, and the temporary pass Kotak gave back.
3. Can be triggered by anyone on the internet, by visiting one web address
   (`api/v1/upi-get-access-token`). No login needed.

Nothing in our own app uses this piece of code any more; the one place that
used it was switched off long ago. The code that does the work is still
there, and so is the web address that triggers it.

## What is wrong with it
It is like a security guard who writes the safe's combination into the
visitor book every time they open the safe, and anyone off the street can walk
in and ask the guard to open it.

- Anyone who can read the server's files (a developer, a support person,
  someone who breaks in) can copy the password from the diary and pretend to
  be us at Kotak.
- Anyone on the internet can keep hitting the web address. Each visit makes
  our server log in to Kotak again and write one more diary entry holding the
  password.
- The password is also sitting in our code, visible to everyone with code
  access.

Nothing bad is known to have happened. The web address points at Kotak's
**test** system, not the live one, which lowers the stakes, but the password is
still a real secret.

## What we are going to change
- The diary entry is removed completely. Nothing about this login is written to
  any file.
- The ID and password are taken out of the code. The code reads them from the
  server's private settings file (`.env`), which is never stored with the code.
  If the settings are missing, the code simply does nothing.
- The public web address is switched off (kept in the file as a comment, so it
  is easy to see and restore), and the code is locked so that it can
  only be used from inside our own software, not from a browser.

## What could go wrong
- If some outside system (not in our code) still calls the web address, it will
  now get a "page not found". We found no caller anywhere in our code, and our
  own only caller has been switched off for a long time.
- The old password stays in the code's history forever. Removing it from
  today's code does **not** make it safe again. Kotak must be asked for a new
  password; that is a manual step, not part of this change.
- The old diary files already on the servers still contain the password until
  someone deletes them.

## Root cause
All line numbers verified on `onestackcbs`. The task title names only the
file; the lines below are confirmed.

Hardcoded credentials, `application/modules/mobile_app/controllers/Payment.php:689-696`:
```php
public function upi_get_access_token()
{
    $url = 'https://apigwuat.kotak.com:8443/auth/oauth/v2/token';
    $grant_type = 'client_credentials';
    $client_id = '<redacted>';        // literal in source
    $client_secret = '<redacted>';    // literal in source
```

Secrets written to a log, `Payment.php:711-718`:
```php
$myfile = fopen("./application/logs/upi/access-token-" . date('Y-m-d') . ".txt", "a");
...
$txt .= json_encode($postField);     // "grant_type=...&client_id=...&client_secret=..."

```
Both the credentials (request) and the bearer token (response) are logged.

Publicly reachable:
- `application/config/routes.php:1383`:
  `$route['api/v1/upi-get-access-token'] = 'mobile_app/Payment/upi_get_access_token';`
- `Payment.php:4`: `class Payment extends Public_Controller`, so there is no auth.
- Even without that route, HMVC resolves `mobile_app/Payment/upi_get_access_token`
  directly: no catch-all route exists in `routes.php`, `cbs-routes.php`, or
  `production/*`. So removing the route alone does **not** close the endpoint.
  The method must also stop being public. CI3 refuses to dispatch non-public
  methods (`system/core/CodeIgniter.php:437`, `! is_callable(array($class, $method))`
  gives a 404). `Payment` has no `_remap`.

Only internal caller is dead code, `Payment.php:1215-1222`, inside `/* ... */`:
```php

$aggregatorId = 'ONES';

```

The transport does not log: `CommonFunctions::upiKotakCall()`
(`application/libraries/common/CommonFunctions.php`) has only commented-out
`echo`s, so no second leak.

## How it will be fixed
1. Delete the log block `Payment.php:711-718`.
2. Replace the literals at `:693-694` with env reads, matching the existing
   idiom (`application/config/applog.php:6`, `$_ENV['X'] ?? default`; `.env` is
   loaded into `$_ENV` by `index.php` `load_env()`):
   ```php
   $client_id = $_ENV['KOTAK_UPI_CLIENT_ID'] ?? '';
   $client_secret = $_ENV['KOTAK_UPI_CLIENT_SECRET'] ?? '';
   if ($client_id === '' || $client_secret === '') {
       return '';
   }
   ```
   Read inside the method, **not** as a `define()` in `constants.php`.
   Constants load on every request, and a `define('X', $_ENV['X'])` with the key
   missing throws an undefined-index notice on every page (the existing
   `AWS_*` defines at `constants.php:99-101` have exactly that shape).
   Return value `''` matches the method's existing "no token" return
   (`:705`).
3. Change `public function upi_get_access_token()` to `private function`, the
   same visibility idiom already used in this file (`Payment.php:3010`,
   `:3114`). The commented-out caller at `:1217` is `$this->`, so it would
   still work if revived.
4. Comment out the route line `routes.php:1383` (user decision: comment, do not delete).

No change to the URL (`apigwuat...`); out of scope.
