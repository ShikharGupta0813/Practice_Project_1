# B2 - Replace HTTP_REFERER in ticket views with site_url/history.back

Asana: https://app.asana.com/1/1139764983605995/task/1217764812919076 | ID: 1217764812919076 | Due: no due date | Part of: Track B — Admin console frontend

---
# PART 1 — In simple words

## What the system does today
Five ticket-related admin pages have a "Go Back" link. Instead of pointing it
somewhere fixed, the page asks the browser what page it came from (the
"referer" header) and sends the link there.

## What is wrong with it
The referer header is just something the browser reports about itself — it is
trivially easy to fake or omit. Using it to decide where a link goes is a weak
foundation for navigation: it can be spoofed, is often missing (privacy
settings, some browsers), and is the kind of pattern that opens the door to
open-redirect-style abuse if it were ever used for something more sensitive
than a "go back" button.

## What we are going to change
Replace the referer-based link with the browser's own built-in "go back one
page" action, which needs no server-provided address at all.

## What could go wrong
Very little — from the user's point of view, "Go Back" behaves the same way,
except it now always works (referer is sometimes empty today) and can't be
tampered with.

---
# PART 2 — The words used here

| Word | What it means, simply |
|---|---|
| `HTTP_REFERER` | A header the browser sends saying what page linked here. Optional and spoofable. |
| `history.back()` | A JavaScript call that tells the browser to go back one page in its own history, no server input needed. |

# PART 3 — The technical version

## Root cause
Exactly 5 sites, all the same "Go Back" button pattern, all raw/unescaped, and
all used as a real navigation `href` (not read-only display):

| File | Line |
|---|---|
| `application/modules/mobile_app/views/communication/client-tickets/view-client-ticket-comments.php` | 10 |
| `application/modules/mobile_app/views/communication/client-tickets/view-client-ticket.php` | 11 |
| `application/modules/mobile_app/views/communication/client-tickets/view-complaint-ticket-comments.php` | 10 |
| `application/views/admin/client-tickets/view-client-ticket-comments.php` | 10 |
| `application/views/admin/client-tickets/view-client-ticket.php` | 10 |

Scope confirmed: `cbs/controllers/Homepage.php`, `cbs/controllers/PartnerContact.php`,
`mobile_app/controllers/bank_onboarding_form/{CompanyContact,PartnerContact}.php`,
`mobile_app/controllers/communication/ClientTicketMaster.php`, and
`mobile_app/controllers/Debugger.php` also reference `HTTP_REFERER` but are
controllers, not "ticket views" — out of scope for this task (the title's "5
ticket views" count matches exactly the 5 files above).

## How it will be fixed
Replace, in each file:
```php
<a href="<?php echo $_SERVER['HTTP_REFERER']; ?>" class="...">Go Back</a>
```
with:
```php
<a href="javascript:void(0);" onclick="history.back();" class="...">Go Back</a>
```
keeping the existing classes/icon/text unchanged.

5 files, 1 line each. Total: 5 lines changed.
