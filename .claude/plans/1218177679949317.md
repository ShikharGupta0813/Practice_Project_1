# PART 1 — In simple words

## What the system does today

When somebody types a web address into their browser to reach this system, the
system has to work out which piece of program code should answer. It does that
by looking up the address in a list.

Those lists are the "routes files". They are two plain text files that pair up an
address with the code that handles it — a switchboard, effectively. There are
about 4,700 lines of these pairings between the two files.

Right now, one of the two files opens with a long standard explanation that came
with the framework the system is built on. The other opens with a single line
that just says "CBS start". Neither says plainly, at the top, what the file is
for or what should and should not be put in it.

## What is wrong with it

Nothing is broken. No customer or member of staff is affected in any way. This is
a housekeeping request.

The practical problem is that a developer opening either file for the first time
has no statement at the top telling them the file holds routes and nothing else.
Over 4,700 lines that matters: it is the kind of file where someone eventually
adds a stray helper function or a configuration value because there was nothing
saying not to.

## What we are going to change

Add a short comment block at the top of each of the two routes files, saying in
plain terms that the file contains only address-to-code mappings and that nothing
else belongs in it.

Comments are notes for humans. The system ignores them completely. No address
changes, no behaviour changes.

## What could go wrong

Almost nothing, and the one real risk is worth naming: these two files decide
which code answers every single web address in the system. An accidental keystroke
in the wrong place while editing them — a deleted character on a route line, an
unclosed comment marker — would take down large parts of the site. The change
itself is only added comment text, but the files it touches are as load-bearing
as any in the project.

That risk is handled by keeping the change to added lines only, changing no
existing line, and checking afterwards that the machine still reads exactly the
same list of addresses it did before, with none added, removed or altered.

# PART 3 — The technical version

## Root cause

Not a defect. A documentation request.

Verified on `onestackcbs`: exactly **two** routes files exist.

```
application/config/routes.php        (~2,970 lines)
application/config/cbs-routes.php    (~1,770 lines)
```

`git ls-tree -r --name-only origin/onestackcbs | grep -i routes` returns only
those two plus unrelated vendor HTML samples under
`assets/custom/plugins/maps-amcharts/`, which are not routes files and are out of
scope.

Note for anyone working from `.claude/docs/architecture.md`: that document lists
four possible routes files, including per-environment overrides at
`application/config/<ENVIRONMENT>/routes.php` and `.../cbs-routes.php`. Those
paths are supported by the patched `system/core/Router.php`, but **no environment
directory on `onestackcbs` actually contains one**. Nothing to comment there.

Current headers:

- `routes.php` — `<?php defined('BASEPATH') ...` then the stock CodeIgniter
  "URI ROUTING" pipe-bar block explaining reserved routes.
- `cbs-routes.php` — `<?php defined('BASEPATH') ...` then `/* CBS start */` and
  straight into `$route[...]` assignments.

## How it will be fixed

Insert one block comment into each file, immediately after the
`defined('BASEPATH')` guard and before any existing content.

`cbs-routes.php` uses plain `/* ... */`; `routes.php` uses the framework's
pipe-bar style. Per `.claude/CLAUDE.md` ("match surrounding style; do not
introduce new patterns mid-file"), each file gets the block in its own idiom.

For `application/config/routes.php`, after line 2, before the existing
`URI ROUTING` block:

```php
/*
| -------------------------------------------------------------------------
| ROUTES ONLY
| -------------------------------------------------------------------------
| This file contains route definitions only. Nothing else belongs here.
|
| Add only $route[...] assignments and the reserved routes below. Do not add
| helper functions, configuration values, database calls or any other logic
| to this file.
|
| CBS module routes live in application/config/cbs-routes.php, which is loaded
| by the patched system/core/Router.php. A route defined later overwrites an
| earlier route with the same key.
| -------------------------------------------------------------------------
*/
```

For `application/config/cbs-routes.php`, after line 2, before `/* CBS start */`:

```php
/*
 * ROUTES ONLY
 *
 * This file contains CBS route definitions only. Nothing else belongs here.
 *
 * Add only $route[...] assignments. Do not add helper functions, configuration
 * values, database calls or any other logic to this file.
 *
 * This file is loaded by the patched system/core/Router.php, after
 * application/config/routes.php. A route defined here overwrites an earlier
 * route with the same key.
 */
```

Both wordings state the required point ("this file is for routes only") and add
the one fact a newcomer most needs: that a duplicate key silently wins, which is
the documented trap in this codebase.

## How to test

1. Confirm only the two routes files changed:

```bash
git diff --stat onestackcbs..HEAD
```

2. Confirm the diff adds lines and removes none — this is the important check:

```bash
git diff --numstat onestackcbs..HEAD
```

The deletions column must be `0` for both files.

3. Confirm both files still parse:

```bash
php -l application/config/routes.php && php -l application/config/cbs-routes.php
```

4. Confirm the route table is byte-for-byte unchanged. This evaluates each file
   in isolation and dumps the resulting `$route` array, before and after:

```bash
git stash && php -r '$route=[]; define("BASEPATH",1); include "application/config/routes.php"; include "application/config/cbs-routes.php"; ksort($route); echo md5(serialize($route)), " ", count($route), PHP_EOL;' > /tmp/routes_before.txt; git stash pop; php -r '$route=[]; define("BASEPATH",1); include "application/config/routes.php"; include "application/config/cbs-routes.php"; ksort($route); echo md5(serialize($route)), " ", count($route), PHP_EOL;' > /tmp/routes_after.txt; diff /tmp/routes_before.txt /tmp/routes_after.txt && echo "ROUTE TABLE IDENTICAL"
```

Expect `ROUTE TABLE IDENTICAL` and the same route count on both lines. If the
hashes differ, a route line was disturbed — stop and inspect before committing.

5. Confirm the comments landed at the top of each file and read correctly:

```bash
head -20 application/config/routes.php && echo "=====" && head -18 application/config/cbs-routes.php
```

6. Smoke test in the browser: open the admin dashboard and one CBS screen (for
   example Admin -> Customer Account Management). Both must load exactly as
   before, confirming routing from both files still resolves.
