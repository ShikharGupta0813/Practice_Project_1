# PART 1 — In simple words

## What the system does today
Every page and button in the admin panel has an address, like `admin/bank-list-view`.
The last word of the first part (`view`, `add`, `edit`, `delete`) says what you are
trying to do. Before letting anyone in, the system reads that word, looks up the page
name in a list of menus, and checks whether your role is allowed to do that thing
there — like a guard checking a guest list for both your name and the room you want.

## What is wrong with it
About 250 addresses do not end in one of those four words. For them the guard cannot
find the room on the list, writes a note that nobody reads, and **lets the person in
anyway**. So any logged-in staff member — whatever their role — can open these pages
and press these buttons, including ones that delete records, change statuses or submit
cash-in / cash-out forms.

When we looked at all of them one by one, most turned out to be leftovers:
- 33 lead nowhere at all (the code they point to was removed long ago).
- 131 are old copies: someone later added a correct address for the same thing, the
  screens switched to it, but the old one was never removed.
- 36 are not used by any screen.

Only 22 are still really used by the screens. 38 of the leftovers and 3 of the used ones
are already being fixed in other open pull requests (#13327, #13245, #13338), so this
task leaves those to them.

## What we are going to change
- Switch off the remaining 162 leftover addresses (the line is kept but turned into a
  note, so it can be switched back on in seconds if ever needed). The back doors disappear.
- Give the remaining 19 used ones a proper ending (`-view`, `-edit`) and point the
  screens at the new address, so the guard really checks them.
- Everything goes in one pull request, split into three separate commits (addresses
  that already lead nowhere, unused ones, renames) so each kind can be reviewed on its own.

## What could go wrong
- If someone had bookmarked one of the 162 switched-off addresses, it will now show
  "page not found". No screen in the code uses them, but there are no production
  logs to prove nobody types them by hand.
- For the 19 renamed ones, staff whose role was never given permission for that
  page will now be turned away. That is the point of the fix, but someone who used to
  get in "by accident" will notice.
- A mistake in a renamed address would break that one button or panel until fixed.

# PART 2 — The words used here

| Word | What it means, simply |
|---|---|
| route | The address of a page or button, and the rule saying which code answers it |
| suffix / action | The last word in the address: view, add, edit or delete |
| slug | The page name the guard looks up, e.g. `bank-list` in `bank-list-view` |
| fail open | When the check cannot decide, it lets you in instead of stopping you |
| caller | A screen, button or script that uses an address |
| duplicate / twin | A second, correctly-named address that leads to the same code |
| super-admin | The main OneStack account (`is_main = 1`), which skips all checks |

# PART 3 — The technical version

## Root cause
`application/core/MY_Controller.php:345-370` (onestackcbs) derives the permission from
URL segment 2. With no recognised suffix the whole segment becomes the slug and the
action defaults to `view`:

```php
$validActions = ['view', 'add', 'edit', 'delete'];
if (in_array($possibleAction, $validActions)) { ... }
else {
    $this->url_slug   = $segment2;
    $this->url_action = 'view';
}
```

`application/libraries/PermissionService.php:119-152` then looks the slug up in
`tbl_sidebar_accordion_menus.menu_link`; not found → logs "Skipping URL" → `return true;`
(line 152). A second fail-open at `:173-199` returns `true` when the role has no access
row. The task title's line numbers (MY_Controller 341-356, PermissionService 127/173)
have moved slightly; the mechanism is unchanged.

- **Disable** the 162 route lines in Appendix A (routes.php 98, cbs-routes.php 64) by
  prefixing `// UNUSED-ROUTE: ` — the convention already used in PR #13327 for the same
  kind of line (consistency rule). Verified: every key is defined exactly once; with them
  gone no other route pattern matches any of these URLs (nothing silently re-routes).

  callers change and the old line is disabled. Otherwise a new suffixed route replaces the old

  `admin/<slug>-<action>/<original path>`.
- `paramlink` columns are not used for slugs (user, 2026-09-30); the live homepage
  (`modules/cbs/controllers/Homepage.php`) appends `-view` to every shortcut, so no
  shortcut can reach a no-suffix route.
