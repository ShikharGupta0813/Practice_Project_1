# PART 1 — In simple words

## What the system does today

Every month OneStack bills each bank and saves the invoice as a PDF in online
storage. In the admin panel there is an "Invoices" tab for a bank. It lists that
bank's invoices with a "Download" link on each one.

The download link simply contains the invoice's file name. When someone clicks it,
the system fetches the file with that name and hands it over.

## What is wrong with it

Two things are missing, and each one is enough on its own to leak invoices:

1. **The download does not check who is asking.** Invoice file names follow a
   simple pattern: bank name plus invoice number or month. Anyone logged in who
   types another bank's name into the link gets that bank's invoice. It is like a
   filing room where you only need to say the name on the folder.
2. **The invoices list does not check either.** The page tells the server which
   bank's invoices to list. A bank employee can change that and see another bank's
   invoice list, file names included.

What leaks is what OneStack charges each bank. That is commercially sensitive, and
no bank should see it for another bank.

## What we are going to change

The download will look the file up in our billing records. Bank staff will only
get it if the invoice belongs to their own bank. The invoices list will refuse to
show any bank other than the viewer's own. OneStack staff keep full access to both.

## What could go wrong

- If some invoice file on storage has no matching billing record, bank staff will
  no longer be able to download it. OneStack staff still can. Every download link
  on the page is built from the billing records, so this should not happen for
  anything shown in the list.
- If a file name contains a character the web address changes in transit, the
  lookup for a bank user could miss and show "File not found". OneStack staff
  are unaffected.

## Root cause

**Line drift:** `download_bill_pdf` is now at `BillGenerationMaster.php:2186`, not `:2179`.

1. `application/modules/mobile_app/controllers/communication/BillGenerationMaster.php:2186`:
   ```php

       $params = ['s3filedir'=>'billing-receipts/','fileName'=>$file_name];
   ```

   login is required, but any admin login of any bank works. Filenames are
   predictable: `str_replace(' ', '_', trim($company_name)) . '-' . $date . '.pdf'`
   (`:2156`), `... '-' . invoice_number . '.pdf'` (`:385`), and `$bankNameClean . '_' . $invoiceNumber . '.pdf'` (`:3623`, `:3751`).

3. The only links to the download are in `modules/cbs/views/bank-management/invoices.php:47, 79, 110`,

Route: `admin/bank-list-view/download_bill_pdf/(:any)` (`cbs-routes.php:1334`). No
per-environment overrides.

## How it will be fixed

- `download_bill_pdf`: for non-OneStack users, look up the row in
  `tbl_bill_details` by `bill_pdf_filename` and require
  `checkCompanyIDMatchesWithSessions($row['company_id'])`. Otherwise
  `show_error('File not found.')` — the same response the method already gives for
  a missing file, so it does not reveal whether a file exists. OneStack behaviour
  is unchanged.
- `invoices()`: after resolving `$id`, deny non-OneStack users whose `$id` is not
  their own. Use the same `echo ...; exit;` style the method already uses for
  `not_found`.

No `partner_id` handling (confirmed: there are no partner-only logins).
