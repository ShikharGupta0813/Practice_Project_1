# B5 - Move in-view SELECTs into controllers; html_escape option output

Asana: https://app.asana.com/1/1139764983605995/task/1217764812919079 | ID: 1217764812919079 | Due: no due date | Part of: Track B — Admin console frontend

---
# PART 1 — In simple words

## What the system does today
Three screens build a "Select Bank" dropdown by asking the database directly
from inside the page template, then print each bank's name straight into the
dropdown option.

## What is wrong with it
Two separate problems. First, a page template is not supposed to talk to the
database — that job belongs to the controller that prepares the page; mixing
the two makes the code harder to follow and to reuse. Second, whatever the
bank's name is in the database gets printed as-is; if that name ever contained
something that looks like HTML or a script tag, the browser would run it
rather than just show it as text.

## What we are going to change
Move the "get the list of banks" step into the controller that already builds
the page, hand the list to the template as data, and make the template print
each value through a safety filter that turns HTML-looking characters into
plain text.

## What could go wrong
Very little — the dropdown shows the exact same banks in the exact same order.
The only visible difference would be if a bank name already contains
characters like `<` or `&`, which would now show as literal text instead of
(potentially) being interpreted as markup — that is the fix working as
intended.

# PART 2 — The words used here

| Word | What it means, simply |
|---|---|
| Controller | The part of the code that decides what data a page needs. |
| View | The template that turns data into the HTML the browser shows. |
| `html_escape()` | A CodeIgniter helper that converts `<`, `>`, `&`, quotes etc. into their safe text form before printing. |
| Stored XSS | Malicious markup saved in the database that runs in someone else's browser when displayed. |

# PART 3 — The technical version

## Root cause
All three sites run the identical query and print pattern —
`SELECT id, company_name FROM tbl_company_master`, then
`echo '<option value="'.$row->id.'">'.$row->company_name.'</option>';` with no
escaping:

| View | Line | Owning controller (currently loads the view with no data) |
|---|---|---|
| `application/modules/cbs/views/equifax/equifax-report-idcbr.php` | 601 | `application/modules/mobile_app/controllers/mis/EquifaxIndividual.php::load_view_partial()` (line 148) |
| `application/modules/cbs/views/equifax/equifax-report-idcr.php` | 616 | same — `EquifaxIndividual::load_view_partial()` |
| `application/modules/mobile_app/views/public/offline-kyc.php` | 238 | `application/modules/mobile_app/controllers/customers/CustomerMaster.php::offlineKyc()` (line ~6923) |

## How it will be fixed
In each controller, before the `load->view(...)` call, run the select once and
push it into the data array:
```php
$this->data['companyList'] = $this->db->select('id, company_name')
    ->get('tbl_company_master')->result();
```
In each view, replace the in-template query + loop with:
```php
foreach ($companyList as $row) {
    echo '<option value="'.html_escape($row->id).'">'.html_escape($row->company_name).'</option>';
}
```
`html_escape()` is CI3 core (`system/core/Common.php`) — no autoload change
needed.
