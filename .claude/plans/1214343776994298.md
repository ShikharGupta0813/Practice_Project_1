# UPI Metrics

Asana: https://app.asana.com/1/1139764983605995/project/1201457139017812/task/1214343776994298  |  ID: 1214343776994298  |  Due: 2026-09-03

## What this task is

**Note on task history:** the original comment on this task ("IN the table,
hovering should be correct") was already delivered by PR #10946 and PR #10955,
both merged 2026-04-29 from branch `sg_api_metrics_1704`, both present in
`origin/onestackcbs` and `origin/onestackcbs-dev`. That work is done. This plan
covers the **new** requirement the user gave on 2026-09-04:

> When a bank has no data, opening an accordion should show an error like
> "Data not found" — the same way "Please select bank first" is shown when no
> bank is selected.

The page is `admin/api_metrics-view` (`ApiMetrics::index`, page header "UPI API
Metrics"), rendering `technology/api-metrics/api_metrics`. It has two
accordions: **UPI Transactions – Last 7 Days** and **UPI Transactions – Today**.

Each accordion body contains, in order: a summary chart, a detail chart, and a
table. Opening an accordion fires three independent AJAX calls
(`api_metrics.php:833-848`).

**What happens today when a bank has no data:** the accordion opens, both charts
render as empty boxes, and the table body gets a single `No data` row from
`renderDailyDynamicTable` / `renderHourlyDynamicTable`
(`api_metrics.php:592` and `:611`). The result reads as a broken page rather
than as "this bank has no data".

**What should happen:** the accordion body is hidden and a single centred
"Data not found" message is shown in its place — visually identical to the
existing "Please select bank first" state.

## Why we are doing it

Small, cosmetic, user-facing. Nothing is broken or leaking; no data, money or
permissions are involved. The impact is that a bank with no UPI traffic
currently looks like a page that failed to load, which generates avoidable
support questions. Being honest about size: this is a polish fix, not a defect
with downstream consequences.

## How it will be fixed

Reuse the mechanism the page already has for the no-bank case rather than
inventing a second one.

That mechanism is already in place at `api_metrics.php:211-219`: a message div
(`#tbl_last7_msg`, `#tbl_today_msg1`) and a content wrapper (`#last7_content`,
`#today_content`), toggled with `.show()` / `.hide()`. The no-data state uses
exactly the same two divs, with the message text swapped.

So: when an accordion's table endpoint returns an empty `res.data`, set the
message div's text to "Data not found", hide that accordion's content wrapper,
and show the message. When data does come back, restore the content wrapper and
hide the message.

The table endpoint is the single source of truth for "is there data" — the two
chart calls are not consulted. This is deliberate: the charts and the table read
the same underlying transactions, and gating on one response avoids a
three-way race between the accordion's three concurrent AJAX calls.

The message text lives in a JS constant at the top of the script block so both
accordions read the same string.

## Plan

1. `git checkout onestackcbs && git pull origin onestackcbs`, then
   `git checkout -b sg_cl_upi_metrics_no_data_message`.
2. Near the top of the script block in `api_metrics.php`, add the message
   constants and one helper:

   ```js
   const MSG_SELECT_BANK = 'Please select bank first';
   const MSG_NO_DATA     = 'Data not found';

   function setAccordionState(msgId, contentId, state) {
       // state: 'data' | 'nodata' | 'nobank'
       if (state === 'data') {
           $(msgId).hide();
           $(contentId).show();
           return;
       }
       $(contentId).hide();
       $(msgId).text(state === 'nobank' ? MSG_SELECT_BANK : MSG_NO_DATA).show();
   }
   ```

3. Rewrite the existing `google.charts.setOnLoadCallback` branch at lines
   211-219 to call the helper instead of six inline `show()`/`hide()` calls —
   `'data'` when `companyId` is set, `'nobank'` when it is not. Behaviour is
   unchanged; this just removes the duplicate toggling.
4. In `loadLast7Days()` (line 228), inside the existing success callback and
   **before** `renderDailyDynamicTable`, add:

   ```js
   const hasData = Array.isArray(res.data) && res.data.length > 0;
   setAccordionState('#tbl_last7_msg', '#last7_content', hasData ? 'data' : 'nodata');
   if (!hasData) return;
   ```

   Keep this inside the existing `try` block so a malformed response still hits
   the existing `catch`.
5. Do the same in `loadToday()` (line 246) with `#tbl_today_msg1` /
   `#today_content`.
6. Leave `renderDailyDynamicTable` / `renderHourlyDynamicTable` and their
   internal `No data` row alone — they are now unreachable for the empty case
   but remain correct as a fallback if either is called from elsewhere.
7. Do not touch `enableTooltips()`, the `setTimeout(enableTooltips, 150)` calls,
   or the `mouseleave` handler — that is the already-shipped April fix.
8. Match surrounding style: 4-space indent inside the script block, `$()`
   jQuery, template literals, and the existing comment-banner format.
9. Commit with the `Asana: 1214343776994298` trailer.
