# PART 1 — In simple words

## What the system does today

Every admin page in this app loads two things: jQuery (the JavaScript toolkit
almost the whole admin panel's buttons, forms and popups are built on), and a
second, smaller script called **jQuery Migrate**. Migrate's only job is to let
old-style jQuery code — written years ago, before the app was upgraded to a
newer jQuery version — keep working today, and to quietly note down every time
it catches the app using one of those old, outdated ways of writing code.

## What is wrong with it

We turned on Migrate's note-taking and loaded the admin homepage once. It
immediately flagged **14 different old-style patterns** actually being used
right now (the task named 13; testing found one more of the same family). Two
examples: writing `$('#save-button').click(function(){...})` (old style) instead
of `$('#save-button').on('click', function(){...})` (current style), and calling
`$.trim(someText)` (old style) instead of `someText.trim()` (current style).

Right now this shim (Migrate) just adds a small amount of extra loading weight
to every page, for every user, on every visit. Nothing is broken today. But it
is a warning light: if jQuery is ever upgraded again, or the app grows a version
that doesn't include this shim, all of these old-style call sites will stop
working with no warning beforehand — a customer-facing form, a report page, or
a settlement screen could simply stop responding to a click.

## What we are going to change

Go through the app's own JavaScript files and the small scripts embedded in
admin pages, rewrite each old-style call to its modern equivalent (almost
always a one-line, mechanical swap), confirm — by reloading the page and
checking Migrate's own report — that the warnings are gone, and then remove
the Migrate shim script itself from the three places that load it, since it is
no longer needed.

## What could go wrong

This does not touch money, accounts or permissions, but it touches **JavaScript
that runs on nearly every admin screen** — buttons, dropdowns, forms, filters.
A mistyped event name or a swapped-argument order would silently break a
button's click handler on a live page, and the only way to catch that is by
actually clicking through the affected pages after each change, not just
reading the diff. Because the true count of old-style call sites can only be
confirmed by loading a page in a real browser (grep alone both over- and
under-counts, see Evidence below), a few genuine sites may be missed on the
first pass and need a follow-up once discovered.

# PART 2 — The words used here

| Word | What it means, simply |
|---|---|
| jQuery | A JavaScript helper library almost all of the admin panel's interactive behaviour (buttons, forms, popups) is written against. |
| jQuery Migrate | A small compatibility script that (a) makes some old-style jQuery calls keep working on the newer jQuery version, and (b) prints a note in the browser's developer console every time it catches one being used. |
| Deprecated | Still works today, but the maintainers have said "stop using this — it will eventually be removed." |
| Event shorthand | The old, short way of saying "run this code when the user does X", e.g. `.click(fn)` instead of the current `.on('click', fn)`. |
| Console warning | A note printed to the browser's hidden developer tools panel — invisible to a normal user, visible to a developer who opens it. |

# PART 3 — The technical version

## Root cause

Confirmed live, not just from grep: jQuery Migrate is loaded and actively
firing on real pages.

- [application/views/admin/_templates/header.php:85,91](application/views/admin/_templates/header.php:85) — every `/admin/*` page loads
  `jquery/3.7.1/jquery.min.js` (CDN) then `jquery-migrate-3.4.1.min.js` (CDN).
- [application/views/admin/_pg_templates/header.php:64](application/views/admin/_pg_templates/header.php:64) and
  [application/views/auth/_templates/footer.php:10](application/views/auth/_templates/footer.php:10) — two more places
  load a **different, stale local copy**, `jquery-migrate-3.0.0.min.js`, instead
  of the 3.4.1 CDN build used elsewhere. Inconsistent, will be reconciled as
  part of removal (see Plan, step 12).

**Live evidence** (not grep): loaded `http://localhost/oneStackLocal/admin/homepage`
in a real browser tab with `jQuery.migrateMute = false; jQuery.migrateTrace = true;`
and read `jQuery.migrateWarnings` after page load. Confirmed 14 distinct
warnings fired from that single page alone:

```
jQuery.expr[':'] is deprecated              [expr-pre-pseudos]
jQuery.isFunction() is deprecated           [isFunction]
jQuery.fn.bind() is deprecated              [pre-on-methods]
jQuery.fn.unbind() is deprecated            [pre-on-methods]      (not in task's named 13)
jQuery.fn.hover() is deprecated             [pre-on-methods]
jQuery.fn.load() is deprecated              [shorthand-removed-v3]  <- actually REMOVED from jQuery 3.x core, only Migrate restores it
jQuery.fn.click() shorthand is deprecated   [shorthand-deprecated-v3]
jQuery.fn.resize() shorthand is deprecated  [shorthand-deprecated-v3]
jQuery.fn.scroll() shorthand is deprecated  [shorthand-deprecated-v3]
jQuery.fn.focusin() shorthand is deprecated [shorthand-deprecated-v3]
jQuery.fn.focusout() shorthand is deprecated[shorthand-deprecated-v3]
jQuery.fn.change() shorthand is deprecated  [shorthand-deprecated-v3]
jQuery.fn.keyup() shorthand is deprecated   [shorthand-deprecated-v3]  (not in task's named 13)
jQuery.type is deprecated                   [type]
```

**Two of the 14 are not fixable in this app's own code**, and need no action:
`jQuery.isFunction()` and `jQuery.type` only occur inside a bundled third-party
file, `assets/custom/plugins/jquery-ui/jquery-ui.min.js` (confirmed via grep —
zero genuine hits in any file OneStack authored). Both are merely *deprecated*,
not removed, in jQuery 3.7.1 core, so jQuery UI keeps working correctly with
or without Migrate present — there is nothing to change and no risk from
leaving it. Per your instruction to fix only the task's own requirement,
`jquery-ui.min.js` is explicitly **out of scope** and will not be touched.

Of the remaining 12, **only `jQuery.fn.load()`'s event-shorthand is an actual
functional risk** — jQuery 3.0 truly removed that meaning of `.load()` (it now
only means the AJAX method); Migrate is the only thing making the old
event-binding usage still work. Every other pattern (`bind`, `unbind`, `hover`,
`click`, `resize`, `scroll`, `focusin`, `focusout`, `change`, `keyup`,
`expr[':']`) is deprecated-but-still-functional in jQuery 3.x core, so nothing
breaks the moment Migrate is removed **as long as `.load()` sites are fixed
first**.

## How it will be fixed

Mechanical, one-line substitutions at each real call site:

| Old | New |
|---|---|
| `.bind('evt', fn)` / `.unbind('evt', fn)` | `.on('evt', fn)` / `.off('evt', fn)` |
| `.hover(fnIn, fnOut)` | `.on('mouseenter', fnIn).on('mouseleave', fnOut)` |
| `.click(fn)` / `.change(fn)` / `.resize(fn)` / `.scroll(fn)` / `.focusin(fn)` / `.focusout(fn)` / `.keyup(fn)` | `.on('click', fn)` / `.on('change', fn)` / etc. |
| `.click()` (no args, trigger) | `.trigger('click')` |
| `.load(fn)` as event binding | `.on('load', fn)` — **must confirm each site is the event form, not the AJAX-content-loading form**, which keeps its current syntax unchanged |
| `$.trim(x)` / `jQuery.trim(x)` | `x.trim()` (native JS) |
| `$.expr[':'].name = fn` | `$.expr.pseudos.name = fn` |

`jQuery.isFunction()` / `jQuery.type` — no app-code fix needed (see Root cause).

`.load()` and `.click()` — the two genuine functional risks — done carefully
in the middle, removal last):

2. `sg_cl_jquery_focusin_focusout` — fix the 2 sites in `custom.js`.
3. `sg_cl_jquery_hover` — fix `application.js`, `custom.js`.
4. `sg_cl_jquery_scroll` — fix 3 files.
5. `sg_cl_jquery_unbind` — fix 2 real files (`fullcalendar.js`, `bootstrap-confirmation.js`).
6. `sg_cl_jquery_resize` — fix 13 files.
7. `sg_cl_jquery_bind` — fix 17 files (`.bind('evt', fn)` → `.on('evt', fn)`).
8. `sg_cl_jquery_change` — fix 21 files.
9. `sg_cl_jquery_keyup` — fix 15 files.
10. `sg_cl_jquery_trim` — fix 30 files, `$.trim(x)` → `x.trim()` only (leave native `.trim()` calls untouched).
11. `sg_cl_jquery_load` — triage all 9 candidate files by hand first (event-bind vs AJAX-load), fix only the genuine event-bind sites.
12. `sg_cl_jquery_click` — triage all 99 candidate files by hand (event-bind vs plain-DOM trigger), fix only genuine event-bind sites; this is the largest PR, expect it to take the most review time.
13. `sg_cl_jquery_migrate_removal` — **after 1-12 are merged**: reload each touched page with Migrate's warning check (see How to test) and confirm zero warnings remain for the 12 in-scope patterns; then remove the `<script>` tag loading Migrate from all three places ([admin/_templates/header.php:91](application/views/admin/_templates/header.php:91), [admin/_pg_templates/header.php:64](application/views/admin/_pg_templates/header.php:64), [auth/_templates/footer.php:10](application/views/auth/_templates/footer.php:10)), removing the stale-vs-current version inconsistency at the same time since both lines disappear together.

Each branch: cut from `onestackcbs`, one commit (or a few, per file group), dev
PR first per standard workflow.

## How to test

For each branch, after the code changes:

1. Start the local admin site, log in, open the affected page(s) in a browser.
2. In the browser console, run:
   ```javascript
   jQuery.migrateMute = false;
   jQuery.migrateTrace = true;
   jQuery.migrateReset();
   ```
   then reload the page and run:
   ```javascript
   jQuery.migrateWarnings
   ```
   Confirm the pattern just fixed no longer appears in the list.
3. Manually click through the specific interactive elements that were changed
   (the button/dropdown/form field whose handler was rewritten) and confirm
   they still behave the same as before the change — this is the only real
   check for a JS handler rewrite; a passing diff review is not enough.
4. For step 13 (Migrate removal): after all 12 branches are merged, reload a
   representative sample of pages (homepage, a DataTables list page, a form
   create/edit page, the login page) with the Migrate script tag removed and
   confirm no console errors and no visibly broken interaction.

No automated JS test suite exists in this repo to run instead — manual
browser verification is required for every branch.
