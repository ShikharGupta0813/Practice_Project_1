# PART 1 — In simple words

## What the system does today
Every admin page is built from a shared "frame" (a header file) that tells the browser which JavaScript files to download. Think of it as a delivery van that carries the same 64 boxes to every house, whether the house needs them or not. Today that is about **3.09 MB** of JavaScript on every admin page — a plain "change a status" page downloads the same amount as the busiest dashboard.

## What is wrong with it
Most of the weight is from files almost no page uses:
- A whole demo dashboard from the website theme (180 KB) that draws stock charts, a world map and a weather widget. None of those exist in any real page.
- Two full copies of the Chart.js charting tool (206 KB and 429 KB), where the second silently replaces the first, so the first is wasted.
- Map, stock-chart and "live tile" tools (about 600 KB) used by that demo only.
- Google Charts files (167 KB) used by 6 pages, loaded on all of them.

Real effect: every user pays for these on every page load — slower pages, more mobile data, more load on the server. Nothing is broken today; this is about speed and waste.

## What we are going to change
Take the unused and heavy files out of the shared frame. The few pages that really need one of them ask for it themselves with a single line at the top of the page (the same way 11 pages already load Google Charts today). The small piece of the demo file that the frame really needs (one function that shows the "welcome" notification) is moved into its own tiny file. We expect roughly **1.7 MB less** on every admin page (3.09 MB → about 1.36 MB, before compression).

## What could go wrong
- A page might quietly use a removed tool and show a JavaScript error or a blank chart. We checked every tool's users by searching the code, and the plan has a click-through list, but a search can miss a tool called in an unusual way.
- If the small notification function is not carried over properly, the "welcome" pop-up stops appearing on every page.
- The change is in the shared frame, so a mistake affects all admin pages at once — hence a full click-through before the pull request.

# PART 2 — The words used here

| Word | What it means, simply |
|---|---|
| Layout / header file | The shared page frame (top part) every admin page is wrapped in; it lists the script files to download |
| Library / plugin | A ready-made JavaScript toolkit (charts, maps, date pickers) |
| Payload | Total size of the files the browser downloads for one page |
| Group | A set of related libraries that a page loads only when it needs them |
| Shadowed | Loaded twice with the same name, where the second replaces the first, so the first was wasted |

Removing all of the above from the layout ≈ **1,730,967 bytes** of 3,089,360 (56%). Gzip transfer will be smaller in absolute terms; the ratio should be similar.

Key rule for "safe to remove": `$(sel).plugin()` throws if the plugin method is missing even when `sel` matches nothing. A call is safe only if guarded by `$.fn.plugin &&`, or inside an `.each(function(){...})` callback over a selector with no matches. Unguarded top-level calls (dashboard.js) force the whole file out, not just its libraries.

## How it will be fixed
1. Both layout headers: delete the script tags for the table above (except the ones that move to a group); delete duplicated `spectrum.min.js` and `icheck.min.js` tags (each is currently included twice — first copy kept).
2. New tiny file `assets/custom/js/global/notif-dashboard.js` containing only `generateNotifDashboard` (verbatim, dashboard.js:4473-end), loaded in place of dashboard.js.
3. Groups = plain `<script src>` tags at the top of the pages that need them (the existing convention — 11 views already do exactly this for `loader.js`; no new helper):
   - chartjs (`js/pages/pie-chart.js`): the two `amortisation-calculator.php` views.
   - googlecharts (`js/charts/loader.js` + `js/charts/google-charts.js`): `admin/dashboard/index.php`, `mobile_app/dashboard/index.php`, and (if verified) the two `company-master/view.php`.
   - googlecharts, loader only: `admin/reports/bank-report-index.php`, `mobile_app/reports/bank-report-index.php`.
   - isotope: the two `onboarding-journey/view.php`.
4. Replace `?v=<?php echo time() ?>` with a file-modified-time version string (`filemtime`) on the two layout tags that use it (`js/custom.js`, and `google-charts.js` which moves into the group). Today the URL changes on every request so the browser can never cache those files.
