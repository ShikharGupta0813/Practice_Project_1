# PART 1 — In simple words

## What the system does today
Every page we send to a browser carries a few short "house rules" (security headers). One says "don't tell other sites which page the visitor came from". Another says "this site never needs the camera, microphone or location". Two sites run our code: the live admin site (admin.onestack.in) and the test site (rbank.in). The live site gets some of its rules from the live server's own settings, outside our code. The test site only gets the rules written in our code.

## What is wrong with it
We checked both sites on 2026-10-05:
- The live site sends the "don't reveal where the visitor came from" rule and the "no camera / microphone / location" rule. rbank sends neither.
- The live site sends the "don't guess file types" rule twice. rbank sends it once.

Nothing has been stolen because of this. But the test site is weaker than the live site, so it is not a faithful practice run, and a fix made on one site can quietly never reach the other.

## What we are going to change
We add the two missing rules to `index.php`, the first file that runs on every request. That file is almost identical on both sites, so one change reaches both, with exactly the values the live site sends today. We also add a small check you can run at any time. It confirms both code branches carry the two rules and asks both live sites what they really send, and it fails if anything differs. Separately, someone with access to the live server must delete the live server's own copies of these rules. That removes the doubled "don't guess file types" line.

We are deliberately not touching anything else: the other rules, the page templates, the web-server rules files, the content-security rule (task NEW-01) and the "always use the secure version" rule (task 23).

## What could go wrong
- **Location block:** the rule "no location" stops web pages from asking for the visitor's location. One screen in our code asks for it: the net-banking payment page (`ibmb/netBanking/payment`). On rbank it would stop working once the rule is added. The live site already sends the same rule, so if that screen is served from the live admin address it is already blocked there. We need you to confirm where that screen runs before this ships.
- **Still doubled on live:** until the live server's own copy is removed, the live site may send these rules twice. Untidy, not harmful.
- **Timing:** rbank gets the change when it reaches the dev branch; the live site only after the production PR. For a while the sites differ. The check will show that.

# PART 2 — The words used here

| Word | What it means, simply |
|---|---|
| Header | A short note the server attaches to every page it sends, telling the browser how to behave. |
| Single source of truth | One master copy of the rules, so nothing can drift. Here: `index.php` for the two new rules, kept identical on both branches and policed by a check. |
| Drift | Two things that should match slowly becoming different. |
| Referrer-Policy | Controls how much of the visitor's previous address is shared when they click away. |
| Permissions-Policy | Switches off browser features (camera, microphone, location) the site never needs. |
| `nosniff` | "Believe the label on the file; don't guess what it is." |
| HSTS / `preload` | "Always use the secure https version of this site." `preload` also puts the site on browsers' built-in list. |
| Branch | A separate line of work in git. Production code lives on `onestackcbs`, the test site's on `onestackcbs-dev`. |

# PART 3 — The technical version

## Root cause
Production's `Referrer-Policy` and `Permissions-Policy` (and a second `nosniff`) are added by the live server layer, outside the repo, so rbank, which runs the repo's code only, never gets them.

Verified live responses (provided by Shikhar, 2026-10-05, `curl -sI .../auth/login`):

| Header | admin.onestack.in | rbank.in |
|---|---|---|
| referrer-policy | `strict-origin-when-cross-origin` | absent |
| permissions-policy | `camera=(), microphone=(), geolocation=()` | absent |
| x-content-type-options | `nosniff` twice | `nosniff` once |
| strict-transport-security | `max-age=31536000; includeSubDomains; preload` | `max-age=31536000; includeSubDomains` |
| x-frame-options | `SAMEORIGIN` | `SAMEORIGIN` |
| content-security-policy-report-only | identical | identical |
| x-xss-protection | `1; mode=block` | `1; mode=block` |

Repo evidence:
- `git grep -nEi "Referrer-Policy|Permissions-Policy|Strict-Transport" -- application index.php .htaccess` on production: 0 matches. The same two header names are also absent from dev's `.htaccess` (read with `git show origin/onestackcbs-dev:.htaccess`).
- `index.php:30` is `header('X-XSS-Protection: 1; mode=block');`, directly after the CSP `header($cspHeader, true);` at `:29`.
- `index.php` is nearly identical on both branches: `git diff --stat origin/onestackcbs origin/onestackcbs-dev -- index.php` shows 2 lines changed (the commented-out CORS `header()` calls at lines 4-5). Lines 7-30 are the same on both, so an edit at line 30 merges without conflict.
- The `.htaccess` files are different files on the two branches (production 431 lines, dev 333; 173 insertions / 272 deletions), which is why this plan does not use them.
- rbank deploys from `onestackcbs-dev` (`.github/workflows/main.yml:6-7`), production from `onestackcbs` (`.github/workflows/Prod-deployment.yaml:5`). No header check exists in `.github/workflows/`.
- Not verified: where on the live server the extra headers are defined (no sudo access).

## How it will be fixed
1. Add after `index.php:30`:
   ```php
   header('Referrer-Policy: strict-origin-when-cross-origin');
   header('Permissions-Policy: camera=(), microphone=(), geolocation=()');
   ```
   Same style as the neighbouring `header()` calls (consistency rule). No existing header is changed or removed, so every currently observed value stays as it is.
2. Add `scripts/check-security-headers.sh` with two modes:
   - `files` (default): `git show origin/onestackcbs:index.php` and `origin/onestackcbs-dev:index.php`, grep for the two exact lines above; exit 1 if either line is missing on either branch.
   - `live`: `curl -sI` against `https://admin.onestack.in/auth/login` and `https://rbank.in/auth/login` (overridable by two arguments); compare `referrer-policy`, `permissions-policy`, `x-content-type-options`, `x-frame-options`, `x-xss-protection`, `content-security-policy-report-only`; flag any header sent more than once; print HSTS for information only; exit 1 on drift.
3. Out-of-repo (server owner): remove the live server's own `Referrer-Policy`, `Permissions-Policy` and `X-Content-Type-Options` definitions. PHP `header()` replaces earlier PHP values but cannot remove a header added by an earlier layer.

Deliberately not changed (all would be separate tasks): the duplicate `header()` calls in eight templates (lines 5-6 of each `template.php`, `index.php:7` `DENY`), `.htaccess`, CSP (`index.php:17-29`, NEW-01), HSTS (task 23).

Limit: `index.php` only runs for PHP responses, not static files. These two headers only matter on documents, so static files are not affected.

## Plan
1. `git checkout onestackcbs && git pull origin onestackcbs && git checkout -b sg_cl_security_headers_single_source`.
2. Edit `index.php`: add the two `header()` lines after line 30 (re-check the line number first).
3. Create `scripts/check-security-headers.sh`.
4. `php -l index.php`, commit once, open the DEV PR to `onestackcbs-dev` via `/task-do`. It should merge without conflict. Production PR only on `/prod`.
5. After rbank deploys: `bash scripts/check-security-headers.sh files` then `... live`. Expect no drift except doubled headers on admin until step 6.

7. Follow-up, not in this PR: a `workflow_dispatch` GitHub Action that runs the script.

## How to test
```
php -l index.php
git diff --stat onestackcbs
bash scripts/check-security-headers.sh files
```
- `php -l` must print `No syntax errors`. The diff must show exactly `index.php` and `scripts/check-security-headers.sh`.
- `files` is expected to fail until the dev PR has merged into `onestackcbs-dev` (dev lacks the lines), which proves the check works; after the merge it must pass.
- Local XAMPP: `curl -sI http://localhost/oneStackLocal/auth/login | grep -iE "referrer-policy|permissions-policy"` must show both headers once each.
- After deploy: `bash scripts/check-security-headers.sh live`, then confirm `x-frame-options` (`SAMEORIGIN`), `x-xss-protection` (`1; mode=block`) and `content-security-policy-report-only` are unchanged from the table in Root cause.
- Manual: on rbank open `ibmb/netBanking/payment` with a test transaction and confirm whether the location prompt still appears; confirm the live behaviour on the live host.
- Production data needed: none beyond the read-only `curl -sI` above.
