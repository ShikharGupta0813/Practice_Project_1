# B3 - Replace localhost refs with base_url; self-host jQuery; remove placekitten

Asana: https://app.asana.com/1/1139764983605995/task/1217764812919077 | ID: 1217764812919077 | Due: no due date | Part of: Track B — Admin console frontend

---
# PART 1 — In simple words

## What the system does today
Three unrelated hygiene issues bundled in one task: (1) some admin pages have
`http://localhost/...` hardcoded instead of using the site's real address,
which breaks in production; (2) a handful of standalone report pages load a
very old copy of jQuery (version 1.11.0, from 2014) from a third-party site
over plain HTTP instead of HTTPS; (3) three ticket-comment pages show a
placeholder cat photo from `placekitten.com` where a real avatar/image should
be.

## What is wrong with it
All three are broken-in-production or third-party-dependency risks, not
security exploits. A `localhost` link never resolves for a real user. Loading
jQuery from an external site over plain HTTP means anyone on the network path
could swap in different JavaScript, and if that CDN ever goes down those pages
break entirely. `placekitten.com` is an external dependency for something that
should be self-contained.

## What we are going to change
Swap `http://localhost` for the CodeIgniter helper that always points at the
real site address; download the same jQuery version and serve it from this
app's own assets folder; remove the placeholder image reference.

## What could go wrong
Very little — these are drop-in replacements. The main risk is scope
ambiguity: a plain grep for "localhost" also matches vendor/config files that
must NOT be touched (see below) — the actual admin-page list needs a final
human sign-off on which 8 (of 11 candidates found) count.

# PART 2 — The words used here

| Word | What it means, simply |
|---|---|
| `base_url()` | A CodeIgniter helper that returns the site's real, configured base address. |
| CDN | A third-party server that hosts common libraries like jQuery for many sites to share. |
| Self-host | Keep a copy of the library inside this app instead of fetching it from elsewhere. |

## How it will be fixed
- **localhost**: replace each hardcoded URL with `base_url('path/to/asset-or-route')`.
- **jQuery**: download `jquery-1.11.0.min.js` once into `assets/js/vendor/jquery-1.11.0.min.js` (or the app's existing vendor JS folder — confirm convention at execution time), reference it via `base_url()` in the 4 files.
- **placekitten**: remove the `<img>` tag (or replace with a local default-avatar asset if the surrounding design expects an image — confirm with a screenshot of the page before deciding).
