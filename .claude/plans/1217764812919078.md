# PART 1 — In simple words

## What the system does today

When a customer pays a bill by card through Kotak's payment gateway, the gateway
sends them back to our "payment result" page. That page is built from pieces; the
last piece is the footer (the copyright strip at the bottom).

The footer has a hidden extra job. If the page is showing a payment, the footer saves
a short note on the server — the order number, whether the payment went through,
and a status message — into a file in the logs folder.

## What is wrong with it

The note is fine; *where* it is written is the problem. A footer is supposed to only
draw the bottom of the page. Anyone checking how payment results are recorded would
look in the payment code, not in the page decoration, so this is easy to miss, easy
to break by editing the footer, and runs every time the footer is drawn with payment
details.

A comparison: the receipt for a sale is being printed by the shop's doormat.

## What we are going to change

Move the note-writing out of the footer and into the payment code, right before it
shows the result page. The note keeps exactly the same file name and the same words,
so anyone or anything that reads these notes sees no difference. The footer goes back
to only drawing the footer.

## What could go wrong

- If the move misses one of the three places the payment result page is shown, the
  note stops being written for that case (for example, failed payments).
- The note is now written a moment *before* the page is drawn instead of during it.
  The time in the file name could differ by a second at most. Nothing else changes.

# PART 3 — The technical version

## Root cause

`application/views/public/_templates/footer.php:4-31` — inside `if(isset($txnDetails))`
the view derives display values and then writes a file:

```php
	$filePath = FCPATH."application/logs/payment-status-trace-".date('Y-m-d-h-i-s').".php";
	$html = "Order ID : ".$order_id."Payment Status : ".$payment_status." \n Status Message : ".$status_message." \n order status : ".$order_status;
	writeLogRaw($html, $filePath, 'w');
```
(`:28-30`). The derived values `$order_id`, `$payment_status`, `$status_message`,
`$order_status` (`:5-26`) are **also** used by the view's own `postMessage` script at
`:50`, so the derivation stays in the view; only the write moves.

Task gives no line numbers; confirmed at `:28-30`.

**Who renders this footer with `$txnDetails` set** (verified):

- Only `Template::public_render()` loads `public/_templates/footer`
  (`application/libraries/Template.php:77`).
- Only `application/modules/mobile_app/controllers/Payment.php` calls `public_render`
  (10 calls).
- `$txnDetails` is set only in `Payment::payment_response()` at `:200`
  (`$this->data['txnDetails'] = $fetchTransaction;`), then amended at `:215-216, 228, 243, 271`.
- Renders after `:200` (so the footer writes today): **`:283`** (`message_page`, success),
  **`:298`** (`payment_failed`), **`:303`** (`message_page`, status unknown).
- Renders at `:143, 165, 193, 311, 317` happen before `:200` or in other branches — no
  `$txnDetails`, no write today. Unchanged.
- Other `$txnDetails` setters (`mobile_app/controllers/api/Insurance.php:941`,
  `api/Insurancev2.php:990`, `apiv6/Insurance.php:990`, two pagination models) render
  via `razorpay_render` → `public/_razor_pay_templates/footer`, which has no write. Not affected.
- No code reads `payment-status-trace` (only hit is the footer itself).

## How it will be fixed

1. Add a private helper to `Payment.php` that reproduces `footer.php:5-30` exactly
   (same status/message derivation, same path, same string, same `'w'` mode):

   ```php
   private function writePaymentStatusTrace($txnDetails)
   {
       $order_id = $txnDetails[0]['order_no'];
       $payment_status = $txnDetails[0]['payment_status'];
       if ($payment_status == 'payment_success') {
           $status_message = 'Your payment was successfull';
       } else if ($payment_status == 'payment_pending') {
           $status_message = 'Order status is pending please check again after sometime in My Transaction menu';
       } else {
           $status_message = 'Your payment was cancelled/aborted';
       }
       $order_status = '';
       if (isset($txnDetails[0]['order_status'])) {
           $order_status = $txnDetails[0]['order_status'];
       }
       if ($order_status != 'success') {
           $order_status = "pending";
       }
       $filePath = FCPATH . "application/logs/payment-status-trace-" . date('Y-m-d-h-i-s') . ".php";
       $html = "Order ID : " . $order_id . "Payment Status : " . $payment_status . " \n Status Message : " . $status_message . " \n order status : " . $order_status;
       writeLogRaw($html, $filePath, 'w');
   }
   ```
   Private, so not reachable as a URL (precedent: `private function upi_get_access_token()` at `:689`).
2. Call `$this->writePaymentStatusTrace($this->data['txnDetails']);` immediately before
   the `public_render` at `:283`, `:298`, `:303`.
3. Delete `footer.php:28-30`. Leave `:5-26` (needed by `:50`).
