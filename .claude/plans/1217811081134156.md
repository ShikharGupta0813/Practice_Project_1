# HIGH - Fix mkdir(…, 0777) sites creating world-writable directories

Asana: https://app.asana.com/1/1139764983605995/task/1217811081134156 | ID: 1217811081134156 | Due: no due date

---
# PART 1 — In simple words

## What the system does today
When the app needs a folder that doesn't exist yet (for an upload, a report, a
log), it creates one with `mkdir()`. Several of these calls tell the operating
system "let anyone write into this folder" (permission `0777`), instead of the
normal, safer "only the web server can write into it" (`0755`/`0775`).

## What is wrong with it
A world-writable folder inside the website's own file tree means that if
anything else on the same server ever gets a foothold — a misconfigured
neighbour site, a compromised process, even a bug elsewhere in this app — it
can drop or overwrite files in these folders freely. Some of these folders are
inside `application/logs`, so a writable log folder can also be used to smuggle
a file in that later gets executed.

## What we are going to change
Change the permission argument from `0777` to a normal restrictive value at
every live site. Two folder families need two different values (see below) —
this is not a single find/replace.

## What could go wrong
Very little for upload/report folders (they're only ever written by the web
process). For folders shared between the web server and a separate cron
process, going too restrictive (`0755`) would let one process create the
folder and lock the other out — those need `0775` instead, matching the
precedent already set by a related fix (`AppLog.php`'s log-directory helper
already uses `0775` for exactly this reason).

---
# PART 2 — The words used here

| Word | What it means, simply |
|---|---|
| `mkdir(path, mode, recursive)` | PHP's "create a folder" call. `mode` is the permission. |
| `0777` | Everyone can read/write/execute. Too permissive for a served folder. |
| `0755` | Owner can read/write/execute; everyone else can only read/execute. Normal for web-only folders. |
| `0775` | Owner and group can read/write/execute; others can only read/execute. Needed when two different system users (web server + cron) must both write. |

The 3 quoted-string sites get their `mode` argument unquoted to a real octal
literal at the same time.
