# CRITICAL - cbs/BankAndOnestackMisReports.php:4388 (xlsxdownload) - any generated MIS/CTR report downloadable by filename, no ownership check

Asana: https://app.asana.com/1/1139764983605995/task/1217811081134119  |  ID: 1217811081134119  |  Due: none

User decisions (2026-09-30): bank staff may download only files that start with
their own bank's name, and OneStack staff may download anything. Files
generated without a bank name get the bank name added to their filename.

**Revised after AI review (2026-09-30), supersedes "How it will be fixed" steps 1-2:**
guessing the owner from the name *prefix* is ambiguous. With banks "Shree" and
"Shree Bank", `Shree_Bank_Book_X.xlsx` could belong to either. The check is now
`isOwnReportFile($filename, $sessionCompanyID)`: a bank user may download a file
only if its **whole name** is their bank's file-safe name (or the bank id, the
generators' fallback), then `_`, then one of the known report names: the 24 fixed
`.xlsx` names, `Bank_Book_<product>_<YYYY-MM-DD>.xlsx`, or
`MIS_Reports_<14 digits>.zip`. Other banks' names are never consulted. The bank
book file is now `<bank>_Bank_Book_<product>_<date>.xlsx`. Tested with 20 cases,
including "Shree"/"Shree Bank" and "ABC"/"ABC Co-op" in both directions. Adding
a new report generator means adding its name to that list.

Round 4: some report names end with another report name
(`Soundbox_Users_Stopped_Transactions` / `Users_Stopped_Transactions`,
`QR_Generated_All_Customers` / `All_Customers`). So banks named "X" and
"X Soundbox" could produce the same filename. Any name that is valid for more
than one bank is now refused for bank users (OneStack users can still fetch it).
29 test cases pass.

Round 6: **a second download route existed.** `downloads/(.*)` (`routes.php:2063`)
goes to `FileController::download()`, which maps to `internal-excel-files/` and
only checks that someone is logged in. The bank-book and zip screens use it
(`downloads/temp/<file>`). The rule therefore moved into a shared helper,
`application/helpers/mis_report_helper.php` (`mis_report_belongs_to_bank()`),
used by both MIS controllers' `xlsxdownload()` and by `FileController::download()`.
In `FileController`, the check applies to bank users whenever the *resolved* path
(`realpath`) is inside `internal-excel-files/temp/`, so `../`, `./` and `//`
variants are covered. Files in other folders are unchanged.

# PART 1 — In simple words

## What the system does today

In the admin console, staff can generate MIS reports (Excel files such as "all
customers" or "customer-wise transactions"). The server saves the file into one
shared folder and then gives the browser a link to download it by name.

Every bank's reports go into the **same** folder. The name is simply the bank's
name followed by the report name, for example `Shree_Bank_All_Customers.xlsx`.

## What is wrong with it

The download page checks that you are logged in, but not **whose** file it is.

Because the names are predictable, a user from Bank A can type Bank B's name into
the download address and get Bank B's customer list, which contains other
people's names, phone numbers and transaction details. It is like a shared
filing cabinet where the drawers are labelled with each bank's name and none of
them are locked.

## What we are going to change

When a **bank** user asks for a file, the server checks that the file's name
belongs to their own bank and refuses anything else. OneStack staff, who look
after every bank, can still download any file.

Two kinds of report are saved without a bank name at the front (the "bulk zip"
of several reports, and the "bank book" report named after a product). They will
now also start with the bank's name, so their owner can be recognised. This also
stops two banks' bank-book files with the same product name overwriting each
other on the same day.

## What could go wrong

- A bank user who today downloads a file that does **not** start with their bank's
  name will be refused. After this change, every report generated for their
  bank starts with the bank's name, so this should only affect files made
  **before** the change. Those can simply be generated again.
- If a bank's name in the system changes, files generated under the old name
  can no longer be downloaded by that bank's users. Generating again fixes it.

# PART 3 — The technical version

## Root cause

`application/modules/cbs/controllers/BankAndOnestackMisReports.php::xlsxdownload()`
is at **:4712** on `onestackcbs` (task says :4388; the method has moved). The login
check and `basename()` are already there. There is no ownership check:

```php
public function xlsxdownload($filename)
{
    if (!$this->ion_auth->logged_in()) { redirect('auth/login', 'refresh'); return; }   // :4714
    $filename = basename($filename);                                                        // :4719
    $filePath = FCPATH . 'internal-excel-files/temp/' . $filename;
    if (file_exists($filePath)) { $this->load->helper('download'); force_download($filePath, null); }
```

Filenames are built from the bank chosen in the request, e.g.

```php
$actual_bank_name = !empty($bank_name_full[0]['company_name']) ? $bank_name_full[0]['company_name'] : $bankid;  // :4220
$safe_bankname = str_replace(['.',' ', ','], '_', $actual_bank_name);                                           // :4221
$excel_file_name = $safe_bankname . '_Mapped_Soundboxes_Branchwise.xlsx';                                       // :4222
```

This pattern is used by 24 generators. Two generators that write into the same
folder do **not** start with the bank name:

- `downloadBankBookReport()` :859, `$product_name['product_name'].'_'.date('Y-m-d').'.xlsx'` (:907), bank from `$this->input->post('bank_id')` (:865)
- `generate_bulk_report_zip()` :5577, `'MIS_Reports_' . date('YmdHis') . '.zip'` (:5586), bank from `post('bankid')` (:5580)

`BankAndOnestackMisReportsExp.php` is a near-copy with the identical
`xlsxdownload()` at **:4716** and zip at **:5590**. It has no route to `xlsxdownload`,
but the class is an `Admin_Controller` reachable through the default module path,
and its zip route exists (`cbs-routes.php:1764`). Same fix, so it is included.

Direct web access to the folder is already blocked
(`internal-excel-files/.htaccess`, `Require ip 127.0.0.1`), so `xlsxdownload()` is
the only way to fetch these files.

**Tenant rule** (project convention): a OneStack user has
`empty($this->session->userdata('company_id'))`, and a bank user has it set. The
helper `checkIfMainSuperadminOrOnestack()` is **not** used, because it blocks other
OneStack staff.

**Prefix collision:** a bare "starts with my bank name" test is not enough. If
one bank is `ABC` and another is `ABC Co-op`, `ABC_Co-op_All_Customers.xlsx` also
starts with `ABC_`. The owner must be the bank with the **longest** safe name that
prefixes the file.

## How it will be fixed

1. New private helper in each controller, next to `xlsxdownload()`:

   ```php
   private function reportFileOwnerId($filename)
   {
       $banks = $this->CommonModel->select(DbTable::COMPANY_MASTER, 'id, company_name', array());
       $ownerId = null;
       $ownerLen = 0;
       foreach ($banks as $bank) {
           $prefix = str_replace(['.',' ', ','], '_', $bank['company_name']) . '_';
           if (strpos($filename, $prefix) === 0 && strlen($prefix) > $ownerLen) {
               $ownerId = $bank['id'];
               $ownerLen = strlen($prefix);
           }
       }
       return $ownerId;
   }
   ```

   Also handle the generators' fallback, where the bank name is missing and the
   file starts with the bank **id**: if no name matches, check
   `strpos($filename, $sessionCompanyID . '_') === 0`.

2. In `xlsxdownload()`, after `basename()`:

   ```php
   $sessionCompanyID = $this->session->userdata('company_id');
   if (!empty($sessionCompanyID)) {
       $ownerId = $this->reportFileOwnerId($filename);
       $ownsByIdFallback = ($ownerId === null && strpos($filename, $sessionCompanyID . '_') === 0);
       if ((string) $ownerId !== (string) $sessionCompanyID && !$ownsByIdFallback) {
           show_404();
       }
   }
   ```

   Refused files get `show_404()`, the same response as a missing file, so the
   check doesn't reveal which files exist. OneStack users skip the check entirely.

3. Put the bank name at the front of the two unprefixed filenames, using the same
   `$safe_bankname` expression the other generators use:
   - bank book (:907): `$safe_bankname . '_' . $product_name['product_name'] . '_' . date('Y-m-d') . '.xlsx'`,
     with `$safe_bankname` computed from `$bank_id` (:865) via `COMPANY_MASTER`,
     exactly as :4219-4221 do.
   - zip (:5586 and Exp :5590): `$safe_bankname . '_MIS_Reports_' . date('YmdHis') . '.zip'`,
     from `$company_id` (:5580).

Not changed (separate):
- Whether a bank user can *generate* a report for another bank by posting
  another `bankid`. The download check now blocks them from fetching it, but
  generation-side scoping is task 40's territory.
- `generate_bulk_report_zip()` returns a `downloads/temp/` URL (:5629) while
  writing to `internal-excel-files/temp/`, so that link looks broken already.
  Left as is.
- `export_loan_emi_dpd_excel()` / `Loan_Report_*` stream straight to the browser
  and never touch the folder, so they are not affected.
- Old files already sitting in `temp/` are not renamed.
