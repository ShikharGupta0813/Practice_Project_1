# PART 1 — In simple words

## What the system does today

An admin user opens the bank MIS reports screen and asks to download the Bank
Book report. The system gathers the customer rows, builds a spreadsheet in
memory, and then saves that spreadsheet as a file into a scratch folder on the
server called `internal-excel-files/temp`. Once the file is on disk it tells the
browser the file name so the user can download it.

Because that folder is only ever a scratch area, the code contains a safety
step: check whether the folder exists, and create it if it does not.

## What is wrong with it

The safety step is in the wrong place. It runs **after** the save, not before.

It is the equivalent of putting a parcel down where a shelf should be, and only
then checking whether the shelf has been built.

On a server where the folder already exists this makes no difference — the save
works, and the check afterwards finds the folder and does nothing. But the
scratch folder is deliberately excluded from the code repository, so it does
**not** exist on a newly deployed server. There, the very first person to click
"download Bank Book report" gets an error page instead of their report. The save
fails outright because there is nowhere to save to, and the request stops before
it ever reaches the line that would have created the folder.

The check will also never help on a later attempt, because the request dies
before reaching it every single time. So the report stays broken on that server
until somebody creates the folder by hand.

There is a second, smaller problem in the same few lines. The save writes to a
full path spelled out from the root of the application, while the existence
check looks at a short path relative to wherever the program happens to be
running from. The two happen to point at the same place today, but only by
accident. If they ever stop agreeing, the check would look in one place and the
save would write to another.

## What we are going to change

Move the folder check and creation so it runs **before** the save instead of
after it, and make the check and the save refer to the folder by the same full
path so they cannot drift apart.

## What could go wrong

On any existing server, nothing changes: the folder is already there, so the
check does nothing and the save behaves exactly as it does today. On a new
server, the report starts working where it previously failed.

The only real risk is a typo in the moved path making the check point somewhere
else. The test steps below check the resulting path directly rather than trusting
that it looks right.

# PART 3 — The technical version

## Root cause

`application/modules/cbs/controllers/BankAndOnestackMisReports.php`, inside
`downloadBankBookReport()` (declared at line 859), lines 907-916:

```php
$excel_file_name = $product_name['product_name'].'_'.date('Y-m-d') . '.xlsx';
$upload_excel_file_path = FCPATH . 'internal-excel-files/temp/' . $excel_file_name;
$spreadsheet->setActiveSheetIndex(0);
$writer = new \PhpOffice\PhpSpreadsheet\Writer\Xlsx($spreadsheet);
$writer->save($upload_excel_file_path);          // line 912 - the write
$path = 'internal-excel-files/temp/';
if (!file_exists($path)) {                        // line 914 - the guard
    mkdir($path, 0777, true);
}
```

Two defects:

1. **Ordering.** `$writer->save()` at line 912 runs before the guard at 914.
   PhpSpreadsheet's Xlsx writer throws when the target directory does not exist,
   so the request aborts at 912 and lines 913-916 are unreachable in exactly the
   case they were written for. The guard can never fire.

2. **Path mismatch.** The write uses `FCPATH . 'internal-excel-files/temp/'`
   (absolute). The guard uses the bare relative `'internal-excel-files/temp/'`,
   resolved against the process CWD. These coincide only because CI's front
   controller runs from `FCPATH`. It is correct by accident, not by construction.

Verified on `onestackcbs`:

- `.gitignore:208-209` reads `# Generated excel files for Monthly MIS` /
  `internal-excel-files/temp`, so the directory is explicitly excluded.
- `git ls-tree -r origin/onestackcbs` returns nothing under
  `internal-excel-files/temp`, confirming it is absent from a fresh checkout.
- Sibling directories that *are* shipped (`internal-excel-files/company/`,
  `internal-excel-files/cbs-sample/`) each carry a `.gitkeep`; `temp/` does not.
- The route is
  `$route['admin/bank-view/bank_mis/download-bank-book-report'] = 'cbs/BankAndOnestackMisReports/downloadBankBookReport';`
  (`application/config/cbs-routes.php:801`).

## How it will be fixed

Hoist the guard above the write and give both the same absolute path:

```php
$excel_file_name = $product_name['product_name'].'_'.date('Y-m-d') . '.xlsx';
$path = FCPATH . 'internal-excel-files/temp/';
if (!file_exists($path)) {
    mkdir($path, 0777, true);
}
$upload_excel_file_path = $path . $excel_file_name;
$spreadsheet->setActiveSheetIndex(0);
$writer = new \PhpOffice\PhpSpreadsheet\Writer\Xlsx($spreadsheet);
$writer->save($upload_excel_file_path);
echo json_encode(['status' => 'success', 'file_name' => $excel_file_name]);
```

`$path` keeps its existing name and `0777` mode, so this stays a reordering plus
a path correction — not a rewrite. The JSON response is unchanged.

Deliberately out of scope: the ~24 other `mkdir()` calls in this file. Those are
already correctly ordered (`mkdir(dirname($tempFilePath), 0777, true)` before the
write, and `if (!mkdir($directory, 0775, true))` guards). Only line 914 has the
inversion this task names.
