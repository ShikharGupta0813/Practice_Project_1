[HIGH] application/modules/mobile_app/controllers/npci-ibmb/NpciIBMB.php:509 - Rate limiting is bypassed when mobile number is unresolved
    category=Security confidence=0.95
    The rate limiting check requires `!empty($mobileNo)`, allowing execution to proceed unchecked if the customer's mobile number cannot be retrieved. This allows an attacker to continuously brute-force M-PIN credentials without lockout for any customer account missing a mobile number. In production, this undermines the credential protection mechanism intended by this fix. Ensure the endpoint fails closed or falls back to an account or customer identifier when the mobile number is unavailable.

[HIGH] application/modules/mobile_app/controllers/npci-ibmb/NpciIBMB.php:1219 - Helper methods declared as public controller actions
    category=Security confidence=0.92
    Declaring `mobile_otp_sent_logs` and `is_max_otp_attempts_exceeded` as public methods in a CodeIgniter controller exposes them as directly callable HTTP endpoints. An unauthenticated external caller can invoke `mobile_otp_sent_logs` directly to inject arbitrary attempt records for any mobile number. In production, an attacker could maliciously lock legitimate users out of payment authorization by triggering denial of service. Change the visibility of these methods to `protected` or `private`.

[MEDIUM] application/modules/mobile_app/controllers/npci-ibmb/NpciIBMB.php:536 - Failed attempt counter does not reset upon successful verification
    category=Correctness confidence=0.90
    Failed attempts logged in `MOBILE_LOGIN_ATTEMPT` are never cleared or marked resolved when the user enters the correct M-PIN. Legitimate users who make isolated typos across separate transactions within the 15-minute window will have those attempts accumulate. In production, this causes legitimate users to be locked out unexpectedly even after completing successful payments. Clear or reset the failed attempt counter for the customer upon successful M-PIN verification.

[MEDIUM] application/modules/mobile_app/controllers/npci-ibmb/NpciIBMB.php:504 - Unvalidated and unsanitized HTTP_X_FORWARDED_FOR header
    category=Reliability confidence=0.88
    Directly reading `$_SERVER['HTTP_X_FORWARDED_FOR']` without parsing or validation allows comma-separated multi-proxy IP strings or spoofed client values. If the string exceeds the database column width for `ip_address`, the subsequent insert into `MOBILE_LOGIN_ATTEMPT` will throw an unhandled database exception. In production, this can crash failed verification handling and produce 500 errors. Use CodeIgniter's `$this->input->ip_address()` to safely extract and validate the client IP.
