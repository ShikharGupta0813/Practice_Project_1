Problem Complexity
Level: HIGH
Summary: This is the central authorization gate for the whole admin console. The change has to stay behaviour-neutral across four fail-open paths and their interaction with the Referer, while preparing a staged rollout to deny-by-default.
Factors:
  - Security-critical code that runs on every Auth_Controller request plus 8 direct callers with different redirect semantics (page vs UI gate)
  - Four distinct fail-open paths, and the Referer path changes which access condition (role-only vs menu-scoped) is evaluated
  - Must keep exact legacy decisions and legacy log entries in warn mode while also computing the menu-scoped answer for comparison
  - Staged enforcement plan in which the reasons depend on each other (missing-referer vs slug-not-found / no-access-row) and on route-rename tasks

Fix Quality
Level: STRONG
Summary: Warn mode is implemented carefully. Legacy decisions are kept on every path, enforcement is controlled by a single reviewed constant, and the shared helpers stop the live and comparison paths from drifting apart. The main gap is that the equivalence evidence is not committed as tests.
Strengths:
  - DENY_REASONS as a class constant makes each future enforcement step a small, reviewable code change instead of an untracked config edit
  - The no-Referer branch reproduces the legacy role-only query, the 'Skipping URL' entry and the allow/deny result exactly, so warn mode does not change behaviour
  - findMenu() and menuCondition() are shared by the live path and resolveScopedDenyReason(), so the comparison cannot drift from the real check
  - Would-deny lines log user_id and role ids, not email, are deduplicated per request, and no-action lines go to their own file to limit noise
  - The scoped comparison runs only when the legacy result is allow, and it is cached per slug|column, which limits the extra database load
Areas for Improvement:
  - Commit the old-vs-new decision harness, or equivalent tests, so later DENY_REASONS changes have a regression safety net
  - The no-Referer branch duplicates the legacy role-only check and log; plan to remove it once 'missing-referer' is enforced so the two paths do not linger
