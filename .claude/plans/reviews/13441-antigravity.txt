[CRITICAL] application/modules/mobile_app/controllers/Bank_register_controller.php:916 - Unauthenticated Access Bypass Exposes Sensitive Bank Credentials
    category=Security confidence=0.95
    The tenant scoping check only executes when `$sessionCompanyID` is non-empty, assuming any request lacking `company_id` is an authorized OneStack user. Because unauthenticated requests also lack `company_id` and this route has no authentication middleware, external callers can bypass the check by omitting session cookies. This allows unauthenticated users or rogue bank users to harvest sensitive CBS API keys and settlement account details for any GSTN. Enforce an explicit authentication and administrator role check before allowing unrestricted cross-tenant lookups when `company_id` is absent.

[CRITICAL] application/modules/mobile_app/controllers/bank_onboarding_form/Bank_register_controller.php:484 - Unauthenticated Access Bypass Exposes Sensitive Bank Credentials
    category=Security confidence=0.95
    The scoping check only runs when `$sessionCompanyID` is present, leaving requests with no `company_id` completely unrestricted. Unauthenticated external callers omitting session cookies will bypass the check and receive sensitive CBS keys and settlement bank accounts. In production, this allows unauthorized actors to access confidential financial institution credentials across all onboarded banks. Require explicit authentication and administrative authorization before allowing GST lookups when `company_id` is not present in the session.

[HIGH] application/modules/cbs/controllers/CbsCron.php:2551 - Unbounded Loop with Individual Update Queries Causes N+1 Database Writes
    category=Performance confidence=0.92
    Executing an individual `$this->db->update()` query per expired customer inside a PHP loop creates an N+1 query write pattern that scales poorly. With large volumes of expired profiles, this sequential update pattern causes severe database lock contention, high latency, and potential script timeouts. In production, this can lead to partial updates and cron failure before all expired KYC records are updated. Replace the loop with a single `UPDATE` query joining `tbl_customers` and `tbl_customer_risk_profile`, or process the updates using batch updates in chunks.

[MEDIUM] application/modules/cbs/views/customer-profile-management/kyc-information.php:266 - Direct Database Query Executed Inside View Template
    category=Architecture confidence=0.88
    Invoking `$this->CommonModel->select()` directly inside the view template violates MVC separation of concerns. Executing database operations within the presentation layer bypasses controller-level caching, complicates error handling, and impairs unit testing. In production, repeated view rendering triggers unnecessary database roundtrips that can degrade page response times. Move the risk profile lookup and expiry evaluation into the controller, passing only the resulting KYC status into the view.
