[MEDIUM] application/modules/mobile_app/controllers/apiv6/Profile.php:12123 - Android min picks the lowest flagged build, so the minimum can never be raised
    category=Correctness confidence=0.80
    Before this change Android returned min == max. Now min is the numerically lowest active build with min_version=1, and flags are set per build and never cleared. Once an old build is flagged, flagging a newer build as the minimum has no effect: the API keeps advertising the old minimum and silently stops forcing updates. Pick the highest (or most recently flagged) min_version build instead, and cap it at max.

[MEDIUM] application/libraries/common/CommonFunctions.php:1655 - UPI QR SMS and WhatsApp notifications disabled for every bank with no toggle
    category=Reliability confidence=0.80

PR Assessment

Problem Complexity
Level: MEDIUM
Summary: The core fix involves version semantics (min vs max), how the admin write path and the mobile read path interact, reads on a replica straight after writes, and backward compatibility of the API contract for installed apps. The merged extras are each small.
Factors:
  - Rows are identified by a flag rather than by ordering, and the admin writer and API reader have to agree on it
  - Deactivate-and-insert pattern with a transaction and replica lag
  - Android and iOS use different version-selection semantics
  - Backward compatibility of the mobile API response for already-installed apps
  - Unrelated changes (notifications, SQL filters, encoding) bundled into the same compare

Fix Quality
Level: NEEDS_IMPROVEMENT
Summary: The iOS save and read logic is careful and well commented. However, the API change drops the data.ios field that clients consumed, leaves two unused queries, and changes Android min semantics in a way that can stop force-updates. The PR also bundles unrelated behaviour changes.
Strengths:
  - Save validates the version format and min <= max, using version_compare consistently
  - Deactivate and insert run inside a transaction, with a failure response driven by trans_status
  - Carries apk_file, bitly_link and siteload_bitly_link forward so the redirect fallback keeps working
  - Device-type header detection is case-insensitive and falls back to request_headers()
Areas for Improvement:
  - Restore data.ios, or delete the unused $iosVersionDetails/$androidVersionDetails lookups
  - Choose Android min as the highest flagged build, capped at max
  - Put notification disabling behind configuration instead of commenting code out
  - Split the unrelated merged changes out of the iOS version fix, as the last commit message intends
  - Add regression coverage for the min == max, min < max and legacy-row cases
