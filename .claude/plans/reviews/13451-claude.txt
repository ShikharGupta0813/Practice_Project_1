[MEDIUM] application/modules/cbs/controllers/CbsCron.php:2542 - Expiry cron skips customers verified only by Aadhaar

[MEDIUM] application/modules/cbs/controllers/CbsCron.php:2552 - Cron loads all expired rows and updates them one by one
    category=Performance confidence=0.85
    The cron loads every matching customer into memory and runs one UPDATE per row, with no batching or transaction. It can also update the same customer several times if they have more than one active risk profile, which inflates the reported count. On a large customer base this means many round trips and a partial update if the run dies midway. Use a single set-based UPDATE with a join or WHERE IN, or process the rows in batches inside a transaction.

[LOW] application/modules/cbs/views/customer-profile-management/kyc-information.php:266 - View queries the database for risk-profile expiry
    category=Architecture confidence=0.85
