[MEDIUM] application/modules/cbs/controllers/CbsCron.php:2552 - Unbounded per-row UPDATE loop with no transaction in KYC-expiry cron
    category=Performance confidence=0.85
    The cron loads every matching customer id and then runs one UPDATE per customer, with no batching and no transaction. On a large customer base this means N round-trips. A mid-run failure leaves a partial reset, and the success count and log hide which rows failed. Use a single batched `UPDATE ... WHERE id IN (...)` (or chunked updates) inside a transaction, and check each update's result.
