# PART 1 — In simple words

## What the system does today

A bank admin can add a contact person for a centre (a small office under a
branch). The form asks for the person's name, phone, email and so on, plus a
**Role** dropdown. The role decides what that person can do once they have a
login.

The dropdown offers four roles: Center Manager, Operation Manager, Tech Manager
and Finance Manager. When the form is sent, the server saves the contact and
creates a console login for them with the chosen role.

## What is wrong with it

The server saves whatever role number arrives, without checking it is one of
those four.

The dropdown only controls what is *shown* on the screen. Anyone can change the
number before the request leaves their browser, which takes no special tools.
So a bank admin could create a login with a much stronger role, such as Bank
Admin, that the form deliberately does not offer.

## What we are going to change

The server will accept only the four roles the form offers. Anything else is
refused with a "please select a valid role" message, and no contact or login is
saved.

## What could go wrong

- If someone somewhere relies on sending a role outside those four through this
  form, it will now be refused. The form cannot show any other role, so a normal
  user cannot do this.
- Editing an old contact who was given a role outside the four (for example
  from before the other options were hidden) will now be refused until a valid
  role is picked. Today the dropdown already shows empty for such contacts and
  the field is required, so this is not a new obstacle.

# PART 3 — The technical version

## Root cause

`application/modules/cbs/controllers/CenterManagement.php`,
`addUpdateCenterContact()` (starts :418) on `onestackcbs`. The only rule on
`role` is a character-set check:

```php
$this->form_validation->set_rules('role', 'Role', 'trim|required|callback_alpha_dash_space');   // :445
```

and the raw value is then used five times:

```php
$role_det = $this->CommonModel->select(CbsDbTable::CBS_ROLE_MASTER, 'role_name', array('id'=>$_POST['role']));  // :470
'role_id' => $_POST['role'],        // :503  contact insert
'role_id' => $_POST['role'],        // :533  contact update
'cbs_role_id'   => $_POST['role']   // :577  new console user (task's 567-578 range: accurate)
'cbs_role_id'   => $_POST['role'],  // :649  existing console user update
```

The form (`application/modules/cbs/views/center-management/center-contact-details.php:309-318`)
offers only these values. 2, 3, 4 and 6 are commented out:

```html
<option value="5">Center Manager</option>
<option value="7">Operation Manager</option>
<option value="8">Tech Manager</option>
<option value="9">Finance Manager</option>
```

`CBS_ROLE_MASTER` is `tbl_cbs_role_master` (`application/libraries/common/CbsDbTable.php:81`).
Other screens list it as `status=1, id != 1` (`BankManagement.php:4749`), which
would also allow Bank Admin, so the table is not a safe allowlist here.

The company is **already** checked: `:422`
`!checkIfMainSuperadminOrOnestack() && !checkCompanyIDMatchesWithSessions($this->input->post('bank_id'))`
rejects a `bank_id` that is not the session's. The roles are global, not per
company, so no tenant condition and no production query is needed.

## How it will be fixed

1. Change the rule at :445 to an allowlist, using CodeIgniter's built-in
   `in_list` (already used in this module, e.g. `BankManagement.php:14788`):

   ```php
   $this->form_validation->set_rules('role', 'Role', 'trim|required|in_list[5,7,8,9]', array('in_list' => 'Please select a valid %s'));
   ```

   A bad value now goes down the existing failure path at :663
   (`$response['msg'] = $this->form_validation->error_array();`), which the view
   already shows next to the field. There is no new error path, and nothing is
   written.

2. After `form_validation->run()` passes, read the value once through the input
   layer, `$role_id = $this->input->post('role');`, and use `$role_id` at :470,
   :503, :533, :577 and :649 in place of `$_POST['role']`.

Deliberately not changed (separate tasks):
- :649 overwrites `cbs_role_id` and `company_id` of any existing user matched by
  email and phone, whatever bank they belong to.
- The same raw `$_POST['role']` pattern in `AtmManagement.php:614`,
  `BranchManagement.php:126` and `BankManagement.php:4373`.
- `:572` passes `$branchId` (undefined; the variable is `$branchID`) as
  `branch_id` for new users. Pre-existing bug, not touched here.
